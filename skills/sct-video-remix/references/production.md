# 从参考到成片：制作与效果闭环

## 先确定本次交付，而不是先写 prompt

用户给原片和商品要复刻：默认只替换商品相关内容，保留原片表达。把目标压成一小段保留/替换/允许变化，缺的事实标未知。通常可自行判断，不要求用户逐份 review 协议。

先找这次用户为什么选原片，再决定执行路线。目标是“这种感觉的商品复刻”，不只是流程跑完或商品相同。判断优先级是用户已说清的偏好、真实媒体证据、模型分析意见。不同分析互相矛盾时，回到相关片段补查，不把后一份更好听的形容词当真源。

选择真实的输入模式：

| 模式 | 实际给视频模型的输入 | 能保留什么／代价 |
|---|---|---|
| video_reference | 图片＋视频，可另有音频 | 直接传连续表演，但也可能带入旧商品、旧口播；不能保证商品替换 |
| image_text | 只有图片＋文字 | 不输入视频或音频；通过原片分析重建表演，不能保证原声/微节奏完全一致 |
| image_audio | 图片＋音频，无视频 | 可传语音节奏；不保证动作因果、商品方向或镜头节奏被恢复 |

三者是生成条件，不是技能档次。“无参考视频”需要标明是否仍用原片派生的垫图、文本或音频。不要为提高效果偷偷把视频/参考语音塞回纯图片文字组。

生成输入与成片声音分开决定：`image_text` 禁止上传音视频，不要求静音输出；原片有口播时，仍用文字指导模型生成口播，不能把“不要添加原片没有的旁白”误读为删掉已有旁白。优先沿用会话已定条件，不擅自去声音，也不默认追加音频参考。

生成端只用图文，或要求换人物/场景仍保持核心时，读取 [纯图文重建与分流](image-text-reconstruction.md)。它处理静态画面能传什么、动态关系怎样写，以及失败后该改哪一层；不增加审批节点。

## 节点与交接物

| 节点 | 输入 | 输出及消费方 |
|---|---|---|
| 分析 | 原始媒体、目标区间、用户目标 | 带时间证据的声画/表演分析＋原始响应；供制作计划使用 |
| 商品与画面 | 商品图/事实、相关原帧 | 商品合同与必要垫图；供计划与视频模型使用 |
| 制作计划 | 上两步文件＋替换边界 | 一份计划：商品、拍摄、声音、镜头内因果/节拍；直接编译生成规格 |
| 执行 | 规格、真实输入、预算 | 平台任务、费用、原始文件；不改写创意，不增加输入 |
| 选片 | 原片、实际规格、结果、用户意见 | 短对照与选片/下一变量；不把模型评分当验收 |

每步可单独交给子代理；交接绝对路径、源区间、版本、必要约束，不需要整段会话。返回真实文件和未解决问题即可。模块分开用于定位损失，不是每个模块都再总结一遍。

交接还带上本次用户真正要保留的体验，以及已排除的误判；只传一份“自然、有感染力”的摘要不够。用现有 `provenance.target` 保存用户请求及已确认的保留/替换边界，不把创作取舍反写成用户授权；`transfer` 短列关键源证据与承接字段。每步可以修正上游猜测，但不能静默换目标。独立检查同时读取原请求、原分析/校正和计划，只找偏离、矛盾和遗漏，不另写第二份 prompt；主代理解决具体冲突后提交。

## 分析：保留配合，而不是动作名词清单

Gemini 分析完整相关区间，原始响应持久化。用现有转录工具保存音频文字/时间，模型不靠记忆补全文。无需本地转录工具也可按可听语气分析，明确未校验逐字内容。

完整上传不等于模型逐帧观看。快速动作/短暂效果若决定目标，应检查视频观察粒度（工作指导中的可选`--video-fps`），必要时显式请求更密采样并记录额外用量。对照本地原帧验证，不把请求值当作网关确已执行的证明，也不把所有误判都归因于采样；普通内容继续复用已有观察。

发现原分析错误时，不覆盖原始返回；在同一分析目录写 `corrections.md`，短列源区间/证据、原判断、采用的修正及仍不确定项。下一节点同时读取分析与校正，已核实的校正优先；制作计划的 `provenance` 保存两条路径，不能只让修正停留在主代理上下文里。校正文件不存在就不强制创建空表。

按实际切镜记录：起始视觉状态→为什么动→接触/变化峰值→怎么自然收尾；把重音、停顿或音乐拍点接到这些事件上。例如“说到转折时才把鞋转向侧面；目光跟着手确认细节；接触后松手，话没停”，比“微笑、抬手、点头、转鞋”更有用。相关镜头交代相机由谁拿/靠什么支撑、朝哪儿、物体在手里/脚上/地面上以及相对高度；“侧面展示”不是机位，“手持感”也不代表自拍。

有声素材提取可观察声线、语速/疏密、语调起伏、重音、气口、句尾；无声素材记录现场声/音乐/切镜节拍。优先准确的少量因果节点，不逐词塞表情，不人为增加表演强度。机器给出的时间单位、动作事实需要与实际媒体交叉核对；硬切到已经穿好，不可推断为免手穿入。

有口播时读取 [说话表达迁移](../../sct-video-remix/references/speech.md)。声音的意群和画面的切镜独立分析，再记录少量关键配合；不能默认一镜一句、一个词一个动作。无口播时不加载说话模板：保留音乐/现场声的推进、揭晓时机和镜头内变化，必要时记录源拍点位置，不凭模板自动添加节拍或旁白。

摄影记录主光方向、阴影/亮暗不均、人物与背景的相对亮度、手机距离/透视、曝光/对焦变化、原片压缩感。不要统一改成漂亮、锐利、棚拍光；也不要为了真实机械叠加污点/噪点。

## 商品与垫图

商品合同只记图中可见或用户提供的名称、配色、结构、标签、支持的主张，以及证据路径。未知尺寸/功效不编造。原片中的卖点不是新商品事实。

垫图以原帧作场景/构图底稿，结合产品参考替换目标，检查前景与背景的每一只商品。用户要求换场景时，原帧只提供要保留的机位/构图，垫图必须呈现新场景；未给场景素材则明确由创作选择，不能反而锁回旧场景。人物母图只在身份必要时用；保留原场景时不另加冲突的场景参考。产品九宫格是可复用辅助，可选且需清晰，不把它伪装成新的产品实拍事实。

垫图默认是本段画面参考，不自动变成强制首尾帧。有产品交互时按平台能力同时输入清晰产品参考，写明各图负责什么。根据本次最重要的表达挑图：若关键是效果反差，给出有证据的前后状态；若关键是翻转，端态之间最容易歧义的侧缘/持握状态比另一张重复产品图更有用。不默认每个动作都多图，也不能让不同角度被误解为不同物件或不同镜头。正确垫图不能保证视频不串色；具体错误以实际成片检查。

## 一份计划直接成为 prompt

计划一次综合分析原文与商品事实，随后 `compile` 只拼接、不总结，输入角色实际写进 prompt（不能只存在本地 role 字段里）。保留原始分析路径以追溯；不把原始素材、摘要、脚本、分镜、工程化 prompt 多次转写当成必要流程。

编译只保证文字没有被再次改写，不保证上游分析充分。先检查用户核心目标对应的分析是否真的有证据：有口播的音色与收音、涉及翻面的实际过程、触发效果的恢复不能只留类别词。缺失时只补相关观察；仍未知就保留不确定，不拿通用“自然女声/拿起商品”填满字段来假装完成。不是给所有素材增加同一张长检查表。

每镜描述动作因果、机位，以及关键声音同步关系。保留参考实际的反应、过渡和收尾；参考急收就不强加松弛尾部，参考热情就不因“反夸张”压低情绪。不要求始终正对镜头或每句话做动作。只锁定决定效果的节点，其他让模型自然连接。

用户直接提供原片、商品相同且没有改词指令时，沿用原台词的词句、顺序、核心卖点与重复强调；15秒放不下时选取完整表达单元，不默认另写一篇。只有用户要改写、商品不同或活动条件确有变化时才局部调整，并保留原文与改动理由；其他来源按其使用边界处理，不能把来源限制变成一律重写广告的理由。尤其不要把功能推荐降成“看这里变色”的画面解说。文字不能精确保证声纹。去声音、重写声线、压缩时长、改变拍摄风格都是实质变化，写入 change。

长原片→15秒：优先保留一个完整表达单元或按真实冗余剪短；确需整体加速时明确速度与损失，不默默改变节奏。叙事功能段可以很长，视频模型段按真实时长限制拆，切分属于生成层。跨段保持同一商品/人物参考与相邻视觉状态，不默认模型都支持首尾帧。功能段不等于生成段。

提交前做一次短的意图对照，存在 `provenance` 即可，不加用户确认门：目标的关键体验→参考证据→本计划如何承接/为什么改变。例如色彩受产品图控制、快切受镜头安排承接、连续推荐由整段语流承接。实际需要模型执行的内容必须出现在 `sound`、`look` 或镜头正文；只写在 `provenance` 不会发给生成模型。不能只查字段非空。检查全局 sound、镜内 delivery/sync 与台词是否互相打架，删掉重复形容词、互斥指令、模型看不到的“比上一版更好”等相对描述。准确精简不是再次摘要；关键措辞保留，编译器只负责原样传输。

## 裂变与批量

优先从已选中的基础版派生；用户正在验证时可从未选中的实验父版派生，明确不是已验收模板。说明改变了商品/人/穿搭/场景/钩子/节拍中的什么，其余保留。只换场景/人/穿搭可用 `vary` 的显式替换入口（见计划合同），保留核心声明和差异；修改商品、台词、节奏则编写关联父版的新计划。一个实验只问一个主要问题；若为修复效果同时改多项，就诚实叫组合改进，不宣称单变量因果。

逐个版本保存输入、prompt、模型、通道、时长、费用和结果。用户要一条先出一条，不先造大流水线或大批量。批量用后端串行恢复；每次生成的花费独立计算。

## 效果验收是闭环，不是评分竞赛

先给真实视频，简短列：表达/节奏是否贴合、商品是否一致、动作与接触是否有因果、声音是否合适、光线/画面是否真实。指出具体镜头或时间，不用一个总分覆盖所有维度。

抽帧能查颜色/身份/结构，不能证明连续动作自然；转录能查文案，不能单独证明品牌发音或情绪。需要听看真实视频。机器审片为定位辅助，有时间错位或事实错判时降级为待核实，不拿它自动选优、加积分循环。先核实可观察现象，再解释原因：切镜要有前后突变证据，局部效果要分别看作用区和参照区，声音来源不能靠听起来相同猜测。机器建议的平台控制能力须另行验证；不能把未经核实的“改用逐帧控制”当修复方案。

声音问题用 `assess --focus sound`，整体模仿/声画错位用 `assess --focus performance`（见工作指导），把核心保留项和允许变化写入 brief，同次传真实参考与结果。通常选一个最能回答当前问题的检查，不每条默认跑两种。后者直接比较完整视频，不自动剪辑，模型仍可能漏掉快速动作。当前宿主无法直接听看时明确使用了什么辅助工具。模型可能偏爱更清晰/更慢的一条，须分开“是否贴合用户参考”与“模型个人偏好”。有声作品交付时说明声音、画面与连续性各自查了什么；尚未核实不能写通过。

一次样片只验证这组条件。改变台词、节奏和表达属于同一声音方向的组合修正，不是严格单变量试验；模型随机性仍在。不要用软件用例数量、机器分数或一条好片宣称完整稳定的生产成功率。用户要强能力，意味着可执行、可定位和可迭代，而不是对未知模型效果打包票。

用户选择优先；技术完成与效果通过分开写。效果不佳时追查原素材→分析→计划→真实调用→成片→审片目标，区分输入缺失、主动改动、装配丢失、模型未遵循和审查漏检，再提出最小可检验改进。机器称过渡成立却没有可辨认的中间过程、触发与恢复证据时，只能标待核实，不拿端态截图推翻用户原速反馈。不要自动重复付费试到满意。

迭代 Skill 时做独立正向验证：给执行代理正常用户请求、更新后的 Skill 与最少原始素材，不给修好的提示词、旧成片或本次诊断答案；从正常入口生成计划和真实结果。主代理在原目标下比较新旧产物，记录中途是否人工救场；救场样片不能算独立流程通过。已有分析仅在证据足够且未受预期答案污染时复用。换了模板可按新签名重分析，避免复制旧校正来伪装重新发现。软件测试只验证传输/兼容性；一次实际改善不证明稳定率，也不能替代不同素材的后续验证。

## 已有实验的适用边界

- 视频参考改善连续表演，是能力上限证据，不证明图片文字流程成功。
- 静态姿态图可改善某个姿势，不能代替连续的手/商品/身体关系。
- 更多动作、更精细表情指令可能更夸张；自然感不是动作数量。
- 音频参考可能改善声音却不恢复动作，仍需查商品朝向和标签。
- 有原视频时也可能把旧商品/配色带回来；无视频时外观更稳并不代表镜头和语气更忠实。
- 原片减尺寸不是天然降积分方案；应以实际计费与用户目标决定是否测试。

以上来自有限真实实验，不是各类商品/模型的普遍成功率。开源版本保留可迁移经验，不携带私人视频、用户身份或实验密钥。
