# 保留爆点，换人换景，直接交付成片

用户要裂变成片时使用；不是另建一条自动改写提示词的链。

## 创意由 Skill 完成，后端不猜爆点

从原参考、已选父版或用户指定的片段提炼一句表达机制，并附原区间：是什么反差/演示/情绪让这条成立，必须看到哪些事件。没有播放或销售证据时称“拟保留的表达机制”，不宣称已验证爆款。把这句话放现有 `provenance.target/transfer`，不再要求用户填写新表。

默认视觉裂变只换明确不同的人物和选定场景，保留商品、原台词、镜头顺序、有效重复、动作过程和节奏。新场景须能完成原演示；例如需要镜中自拍、桌面支撑或透过镜片看焊点，就在新地点保留相同拍摄关系。换场景不是把旧景名称替换成一个新名词。

逐镜从对应原帧制作新的画面参考，保持新人物/地点一致，不用一张共享构图包全部镜头。清理旧身份/旧地点图和冲突文字。已有计划用 `vary`，已有整片用 `vary-assembly`：只派生受影响的镜头，保存差异，没改的镜头保留原件。父版尚未经人选中时明确是实验父版，不叫已验收模板。

用户另外明确要“改变开场钩子/演示顺序/台词”时，才做关联父版的新计划，明确改动及商品事实依据；不能把这种创意改编塞进仅换人换景的控制合同。不为了看起来不同而删掉关键演示或加大表演。

## 从准备好的镜头直接跑到成片

新候选提供 `produce`。Skill 完成分析、垫图和普通 `compile/vary/vary-assembly` 后，只写下面这一份薄任务合同；用户不需要手动逐个运行镜头和拼接。它引用已登记版本，不自动分析、写词、生图或判断好坏。

```json
{
  "format": "video-remix-production.v1",
  "id": "new-person-new-room",
  "budget": 48,
  "estimate_per_job": 24,
  "assembly": {
    "format": "video-remix-assembly.v1",
    "id": "new-person-new-room-cut",
    "clips": [
      {"variant": "new-shot-01", "in": 0, "out": 2},
      {"variant": "new-shot-02", "in": 0, "out": 2}
    ],
    "audio": {"mode": "clips"}
  }
}
```

示例金额不是实时报价，区间不是默认剪法。将 `vary-assembly` 输出的确切组装合同放进 `assembly`，或按真实单镜/多镜制作清单填写；不重新摘要。单镜用一个 clip；声音沿用本次真实安排，不能为直出默认静音或复用原声。v2 登记连续音轨仍按分镜指导的明确来源规则。

通过项目固定版本启动器运行：

```sh
--project <目录> produce /absolute/production.json
--project <目录> produce /absolute/production.json --execute --wait 30
```

第一条只读预览生成输入、预算和组装清单。第二条按原顺序串行生成/下载，所有所需原文件完成后组装。平台未完成时返回 `pending`，再次运行同一命令继续原任务，完成的镜头不重交；只有已授权的具体新版本会产生费用。失败/结果不明会停，绝不以机器评分自动重抽。

`budget` 覆盖合同内所有唯一生成版本，**包含此前已发生的费用**；不是新增额度，重复引用一个镜头只计一次。外部已登记音轨没有新视频生成费。平台回报高于预估时停止后续；冻结任务后改预算/规格/组装必须新ID，原任务证据保留。`productions/<id>/` 保存冻结合同、恢复状态和最终文件路径；原片仍在 `variants/`，成片在 `assemblies/`。默认后端升级不改变已有项目锁。

直出完成只表示文件已生成、真实区间已组装。交付先给成片与极短差异/费用，镜头原件保留。测试期可做目标明确的辅助检查并提出单镜替换建议；不能把机器建议写成人已选中，或宣称能代替客户未知的审美标准。
