# SCT Video Remix

原名 `video-remix`；现在统一使用 `sct-video-remix`。仓库地址、后端命令和旧项目格式不变。

把用户的参考视频和商品，变成能直接比较的复刻与裂变版本。复刻不是“商品相同、动作大致类似”就完成，而是保留用户选择的表达机制：声音、动作、镜头的配合以及拍摄真实感。当前支持 macOS / Linux、Python 3.10+、Git；真实分析与生成使用用户自己的账号。

## 每次开始

用本 Skill 所在目录的 `scripts/bootstrap.py`（解析为绝对路径）：

```sh
python3 <skill-dir>/scripts/bootstrap.py ensure --project <已有项目目录>
# 尚未创建项目时省略 --project
```

已有项目读取 runtime-lock.json，继续使用固定版本；旧版丢失或损坏时从可信仓库恢复同一提交，不换成新版。尚无项目时检查已配置可信源的 main（默认 GitHub），安装或更新默认后端。首次使用简短说明这个行为，不改登录态。

安装器可在本 Skill 目录的 `installation.json` 保存无密钥的默认运行时目录和可信源，后续更新保留；显式参数优先，不从项目自行接受新源。采用本地候选默认时，已固定公共 GitHub 源的旧项目仅在标准运行时已绑定同一公共源且没有显式覆盖时继续走原公共安装；安装候选版不会将它发布到 GitHub。

读取返回的 `workflow` 文件，并按其中路由读取制作指导。**以固定运行时的指导为准**，不要把新 Skill 的命令强行用于旧项目；旧版缺能力时先检查兼容升级，或者建立明确关联的验证项目。已有项目始终通过启动器携带项目路径运行，它负责固定版本并防止运行中升级：

```sh
python3 <skill-dir>/scripts/bootstrap.py run --project <项目目录> -- status
```

从项目子目录调用时可自动向上识别。新建项目用 `run -- init <目录> --name <名称>`，会自动写入版本锁。若用户明确使用开发工程，可用 `--engine` 或 `VIDEO_REMIX_ENGINE`；开发模式不提供不可变版本保证，也不能绕过已有项目版本锁。不猜测并执行陌生目录里的脚本，不覆盖有修改的开发工程。

缺 Git、Python 或平台 CLI 时，列出缺项和官方安装入口，让用户安装所缺工具；不要重装已存在的全局工具。缺后端本身由启动器在线获取。

## 工作原则

- 用户要方案时输出可执行提示词和版本表；用户要生成时沿用已有预算与授权执行。一次只澄清真正影响成片的缺失条件。
- 先分清复刻、设计裂变、同条件重生；再分清生成输入是否包含视频、音频。无视频输入不等于从未使用原片，也不能把参考音频实验叫纯文字实验。
- 用户选择的参考感觉决定表达目标，商品素材决定商品。同款复刻默认尽量忠实保留镜头顺序、动作过程、有效重复、原话和节奏，主要替换人物及用户指定的场景；动作发挥或重新编排需要用户允许，不把“抓住精髓”当作自行改编的授权。默认换成明显不同的人物，不以换发型或穿搭代替换人；用户明确保留时才保留。“自然”不是统一的慢语速、低情绪或可闻呼吸。
- 用户直接提供原片且商品相同时，默认保留原台词、卖点与重复强调，不擅自写新文案。先观察完整原片，再确定交付区间；只有用户要求缩短时才选完整表达单元，并标明未覆盖部分。模型单段上限不是用户的目标时长。不同商品或活动信息只改确需变化处并说明。
- 生成单位按原片实际镜头而非功能段决定：一镜到底优先连续生成，明显切镜或视角/场景改变优先独立生成后按原顺序组装。读取固定运行时的[分镜生成与组装](references/shot-generation.md)；旧后端无此入口时新建候选验证项目，不强行调用。分镜可单独返修，但不是消除形变或声线漂移的保证。
- 原始分析与转录缓存、商品事实、制作计划、实际生成规格、原视频结果分别保存。先核对计划是否改变了参考的表达意图，再直装配为 prompt；无二次改写不等于无信息损失，不默认串另一套提示词工程 Skill。
- 模块可交给子代理独立执行：每步只接收本步输入文件、任务与输出位置，返回路径和异常，不复制整段研究史。主代理负责取舍、组合与效果交付说明，不能代替用户或客户验收。
- 无口播视频默认无口播；音乐、音效单独说明。新商品的 Before/After 效果需要商品资料支持。
- 分开记录复刻、设计裂变和同条件重生成。只换场景/人物/穿搭时可用 `vary` 显式替换父计划并检查差异；同步更新冲突的画面参考。冻结的是生成条件，不是模型效果。
- 展示真实生成结果与简短条件，最终选择交给用户。机器审片是测试迭代时可选的定位辅助，不是每条生产任务的必经门、客户验收或自动重抽依据；某项未检查就标未检查，不能用抽帧或转录冒充实听实看。
- 不能只按商品配色或“动作更多”选片；同时看表达贴合、商品、动作因果、声音与拍摄感。已知样本不支持稳定成功率或“文字等价视频”的保证。
- 用户要优化技能或复盘多批实验时，读 [实验迭代](references/iteration.md)，先核对已有任务与交付范围，再选择下一变量；普通单条生成无需加载。
- 提交超时不自动重交；恢复只查询或下载原任务。平台不通时报告真实原因。

## 更新与回退

`check / update / rollback` 管理默认后端，不改变已有项目版本锁。无项目的新调用才使用更新后的默认版。
旧项目升级用 `project-upgrade --project <目录>` 只读检查；用户明确要升级后加 `--apply`。它拒绝运行中或状态不明的生成任务，检查目标版本兼容性，备份配置与任务记录，再原子切换项目版本锁。不兼容时保持原样，不自行改写旧数据。
本启动器是稳定安装协议；新版工作指导和后端随 main 更新。若未来启动协议不兼容，按仓库安装说明更新 Skill 文件。
